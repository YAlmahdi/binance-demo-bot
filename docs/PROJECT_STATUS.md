### Frozen v1 wire specification

Schema `M6_BINDING_CONTENT_V1`, algorithm `SHA256`, domain bytes `b"FUTURES_AI_LAB\0M6\0BINDING_CONTENT\0V1\0SHA256\0"`. Canonical bytes are domain followed by one root record frame. Every frame is one ASCII tag byte, unsigned 64-bit big-endian payload byte length, then exactly that payload. No implicit conversions, normalization, native byte order, repr, object IDs or unordered iteration enter the wire.

| Tag | Exact payload |
|---|---|
| N | Empty (`None`). |
| B | One byte 00 or 01 (exact bool, distinct from int). |
| I | Sign byte 00/01 followed by shortest unsigned big-endian magnitude; zero is sign 00 with empty magnitude. Negative zero and leading magnitude zeros have no encoding. |
| D | Finite Decimal's exact `as_tuple()` sign byte, framed I signed exponent, U64 digit count, then one byte per coefficient digit 0–9. Signed zero, trailing zeros and exponent representation are preserved without arithmetic or rounding. |
| S | Each Python string code point as U32 big-endian, including surrogates; no normalization or UTF-8 substitution. Empty string is empty payload. |
| E | Framed S stable enum schema ID followed by framed S exact value. |
| T | U64 element count followed by that many complete frames. |
| R | Framed S stable record ID, U64 field count, then ordered pairs of U16 field number and complete value frame. |

### Capture, ordering and resource limits

Before deep capture, M6 checks exact caller budgets, child budget configurations/ceilings and shallow M3/M4 collection lengths. Capture clones every supported record from exact checked children. Serialization and M5 use the same owned capture. Ordinary raw-record field replacement during capture is rejected when detectable; changes to original records after capture do not change the capture. Immutable primitives/Decimals are shared; enums are trusted shared singletons with boundary rechecks. No atomic account/database observation, signature or same-interpreter adversarial security is claimed.

Only after FULL M5 sufficiency does encoding sort M3 required IDs and keyed plan/envelope/binding rows by position ID, alternative M1 scenarios by scenario ID, and M4 snapshot/evidence rows by `(owner_id, source_id, version, snapshot_id, revision)`. M3 uses keyed sets/maps, M1 assesses alternatives then sorts diagnostics, and M4 matches refs/maps, so these presentation orders are nonsemantic. Funding observations, expected settlements, lifecycle events and evidence event IDs keep their declared order. Duplicate/invalid/unsorted meaningful sequences fail child validation before successful serialization; normalization cannot repair them.

Caller `EncodingResources` requires exact nonnegative U64 integers: `max_nodes`, `max_depth`, `max_string_codepoints`, `max_string_bytes`, `max_decimal_digits`, `max_exponent_bits`, `max_integer_bits`, `max_canonical_bytes`. Nodes include repeated occurrences and schema metadata frames; root depth is 0. Text counts include schema IDs and enum values; encoded text bytes are four times code points. Decimal coefficient digits are cumulative; exponent magnitude bits must satisfy both exponent and integer limits; integer magnitude bits are bounded per integer. Framing and domain bytes count exactly. Measured total bytes must fit U64 and Python `sys.maxsize`; representability/budget overflow rejects before the output buffer. M6's encoding limits are outside the committed raw payload; ALL raw M3/M4/M5 processing budgets ARE committed and remain independently enforced.

The reviewed accepted raw-schema graph is acyclic and bounds recursive capture depth; malformed nested structures cannot introduce recursive schema paths. Expanded capture/plan storage is O(nodes + Decimal digits); output storage is O(bytes), including a temporary mutable buffer and immutable copy; sort work is O(n log n). Existing child walks add bounded repeated work. Already allocated input objects, Decimal.as_tuple temporary allocation before digit checking, generous caller limits, Python allocation overhead and malicious concurrent interpreter mutation remain limitations. These are caller processing budgets, not universal production/resource or financial caps. No OS sandbox claim is made.
